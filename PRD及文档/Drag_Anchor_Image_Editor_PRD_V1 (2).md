## 1. 依据与决策口径

本文件依据本轮讨论及用户草图 2434.jpg，不依赖未读取的历史技术文档。实施仓库路径、真实上游接口、账号余额及部署环境尚未提供。

| 口径 | 内容 |
|---|---|
| 用户意图及本版产品基线 | 独立 Image2.5 编辑网站；单主图、多参考图；悬停选物、拖拽建立关系；多个操作积累后统一生成；同关系同编号同颜色；生成历史保存且可打开 |
| 本版补充规则 | 替换模式为 MVP 主路径；选区纠正、冲突处理、任务恢复及验收规则按下文执行 |
| 需要技术验证 | 点提示分割及部署位置、悬停延迟、图像模型多参考图与 Mask 能力、放置控制、批量与串行策略 |
| 不能当成事实 | 有起点/终点就必然能准确分割；只分析局部就必然省算力；某个模型名字就代表渠道支持对应参数 |

本版将 Image2.5 作为指定的核心图像编辑模型。Codex 必须核对实际模型 ID、渠道文档和调用结果；本文件不确认目标渠道已支持全部编辑参数。不能静默换成其他模型；凭证或渠道能力缺失时继续独立工作，并明确保留真实生成验收未完成。

### 1.1 独立网站定位

- 产品有独立入口、导航、编辑工作区、生成历史页和历史详情页，可独立开发、启动和部署。
- 不要求用户先进入博观后台，不依赖博观页面容器或账户才能完成主链路。现有代码中的通用模块可以复用，但运行依赖需在独立项目内明确。
- 生成在本文件中指使用 Image2.5 完成图像编辑并输出图片。本次新增不扩展为纯文本从零生图、视频编辑或完整商业收费平台。
- 最小范围可以先服务一个已授权的站点使用者。若网站开放多人使用，历史、素材和项目必须按账户隔离；不能把共享历史列表当作用户个人历史。

## 2. 用户、目标与范围

### 2.1 典型场景

电商运营或设计人员已有一张人物、商品或广告主图，希望借用参考图中的鞋子、裤子、包等元素，完成主体或商品替换。用户知道“拿什么、改哪里”，但不希望反复用文字描述多张图片的对应关系，也不希望先在其他工具抠图。

典型任务：从参考图 A 取鞋，拖到主图鞋的位置；从参考图 C 取裤子，拖到主图裤子的位置；最后生成同时完成两处替换的结果。

成功标准：用户能明确看到每条替换的源与目标，纠正选区，连续建立多个关系，生成并对比下载结果；关闭页面后仍能从历史打开结果，恢复对应编辑状态并继续工作。目标区域内完成自然替换；目标外人物、姿势、构图及背景尽量保持。

### 2.2 MVP 范围

| 优先级 | 功能 |
|---|---|
| P0 | 单主图、多参考图上传与切换；悬停选区预览；拖拽起点与终点；源/目标选区锁定；多条 Mapping；稳定编号与颜色 |
| P0 | 候选选区切换、圈选纠正；目标区域标识；编辑清单；删除、撤销、重做；补充要求；统一生成 |
| P0 | 真实生成接入；任务状态与失败恢复；原图/结果对比；下载；草稿恢复；真实能力和模拟模式明确区分 |
| P0 | 选区计算中反馈；过期结果丢弃；保留原始选区及处理版本；生成前依据实际编辑范围检查冲突 |
| P0 | 独立网站导航；生成历史列表与详情；打开图片；恢复历史编辑快照；以结果继续编辑；素材与输出持久保存 |
| P1 | 抠图代理预览；放置位置与大小调整；语义名称自动补全；每条关系选填短标签 |
| 后续 | 新增物体模式、旋转/透视编辑、完整图层树、精细画笔、移动端、视频逐帧替换、多版本云端协作 |

MVP 以桌面鼠标操作为主，不要求移动端完成拖拽。抠图代理及缩放是增强项：技术验证通过且不延误主链路时可以一并实现，否则明确列为未交付。

### 2.3 默认限制

以下是本版产品建议默认值，不是模型官方限制。Codex 可依据已验证能力降低并在界面说明，不能静默截断素材。

- 1 张主图、最多 8 张参考图、每次最多 5 条替换关系。
- 接受 JPEG、PNG、WebP 静态图片，单张不超过 20 MB；不接收动画或 SVG。
- 输出默认沿用主图比例；实际支持尺寸、像素上限、处理缩放和输出格式由调研落实，超限上传前或生成前告知。
- 默认模型通过服务端配置确定；普通用户无需理解分割模型或接口参数。
- 第一版不新增付费套餐。使用独立网站自身的身份、资产和任务管理；已有服务能力可复用，但不能要求先打开博观。显示实际调用成本或明确的估算，不伪造余额与扣费。

## 3. 页面与完整链路

### 3.0 网站结构与导航

网站导航至少包括“新建编辑”和“生成历史”。有当前草稿时提供“继续编辑”。首页直接进入工作区或显示近期项目与新建入口，不要求额外营销落地页。

| 页面 | 必需内容与打开行为 |
|---|---|
| 编辑工作区 | 原有双图拖拽工作区；显示项目名称、保存状态及历史入口 |
| 生成历史 | 结果缩略图列表、任务状态、生成时间、项目名称；最新在前；支持全部/成功/处理中/失败筛选，部分完成和保存异常单独标识 |
| 历史详情 | 可放大查看、下载结果；查看本次原图、参考图、编辑清单、补充要求和可用的参数；恢复编辑或以结果继续 |

历史详情需有稳定的记录地址，刷新和直接打开均有效。具体路径由实现确定；链接只定位记录，不代表公开分享或绕过权限。历史结果不必额外打开第三方模型页面。

### 3.1 页面布局

按用户草图实现双工作区，不强制图片同宽高拉伸。主图与参考图分别等比适配，保留完整可视区域。

| 区域 | 位置与内容 |
|---|---|
| 顶部工具栏 | 项目名称、保存状态、生成历史入口；撤销、重做、清空编辑、对比、生成。生成前显示待执行操作数 |
| 主图工作区 | 左侧；被修改的图。展示目标选区、编号；放下后仍保留原图像素作为基底 |
| 参考图工作区 | 右侧；当前参考图。支持悬停高亮、源选区、拖拽 |
| 参考图导航 | 紧邻右侧工作区的竖向缩略图；当前图高亮；添加、删除；溢出滚动 |
| 编辑清单 | 工作区下方；每条显示编号、源参考图缩略图、目标位置、状态及删除/修改入口 |
| 补充要求 | 编辑清单下方；用于材质、宽松度、写实程度等无法由拖拽表达的要求 |
| 结果区 | 成功后展示结果、原图对比、下载、打开历史详情及以结果继续编辑；不自动覆盖当前主图 |

普通用户默认看到“编辑操作”和“补充要求”。AI Prompt 可折叠查看或复制，第一版不提供直接改写完整 Prompt 的入口，避免文字和 Mapping 状态分离。

### 3.2 用户主流程

1. 打开独立网站，新建编辑或从历史恢复项目；上传主图和参考图。上传分别显示处理中、可用或失败，失败文件可以单独重试。
2. 切换到要取素材的参考图；图片准备期间提示“正在准备选区”。鼠标停止在某对象上后出现选区轮廓。
3. 若选区不对，切换候选或进入“精确选择”圈选纠正。用户必须能判断选中的是裤子、腿还是整个人。
4. 在已确认源选区按下并拖动。显示跟随鼠标的缩略代理；有透明抠图时使用抠图，否则使用有边框的裁剪缩略图。
5. 拖入主图，显示当前目标候选区域；在目标区域松手，锁定终点和目标选区。选区未准备完成时进入“确认目标”，不创建虚假的可执行关系。
6. 建立 Mapping ①；源和目标同编号同颜色；编辑清单显示对应关系。松手不触发图像生成。
7. 继续从当前或其他参考图拖拽，建立 Mapping ②、③……；必要时纠正目标、调整允许的放置参数、删除或撤销。
8. 填写可选补充要求，点击“生成（N 项编辑）”。系统检查素材、选区、冲突和实际模型限制，展示已知费用或估算范围。
9. 生成期间展示排队/处理中，防止重复提交。提交时即创建历史记录，草稿和此次任务快照分别保留；离开编辑页后可在历史查看进展。
10. 成功后对比、下载或返回修改；最终输出保存完成后记录为成功。失败后查看明确原因，保留全部关系；用户决定是否重试。
11. 下次打开网站，从“生成历史”点击缩略图打开对应详情；可查看图片、下载，或“恢复当时编辑”加载原主图及关系快照。
12. 点击“以结果继续编辑”时，将所选结果作为新主图创建新草稿，重新准备选区，再进行下一轮编辑；新结果另建历史，不覆盖旧结果。

## 4. 核心业务规则

### 4.1 悬停、锁定与选区纠正

- 悬停给出候选预览，不等于已经确定。移动时丢弃过期返回，避免上一个点的结果覆盖当前点。
- 尚未得到当前点对应的选区时，显示计算中反馈，不显示旧点结果冒充当前候选；反馈与请求控制见第 4.9 节。
- 用户按下时锁定当时确认的源选区和源锚点；拖动过程中源对象不能随鼠标重新识别。
- 无可用选区时，不用一个固定矩形伪装“识别成功”；提供准备状态或圈选入口。
- 候选区域使用按钮或 Tab 切换；悬停期间不占用滚轮，滚轮保留页面/工作区原有行为。
- 源和目标均支持圈选纠正。若没有模型精修，手绘多边形本身可以作为明确标注的手动选区，不能称作 AI 自动精修。
- 点提示结果可能是单只鞋、双鞋、裤腿、整条裤子或整个人。由用户确认范围；不强制模型类别作为选择条件。
- 服装替换可需要完整人体上下文，不能仅因锚点存在就裁掉所有背景或人物信息。

### 4.2 起点、终点与替换语义

- 起点回答“从参考图取哪个对象”；终点回答“替换主图哪个对象/区域”。
- MVP 默认“替换”，不是把源图像素直接粘贴进去。源对象保留款式、颜色和细节，生成时适配目标姿态、视角、光照及遮挡。
- 终点是选择提示，不一定是最终对象中心。源锚点也不一定在源对象中心。布局初始化应依据确认后的选区，不能把落点直接当作所有对象的中心。
- 主图落点无对象、候选不明确、落在图片外时不创建 ready 关系；提示重新选目标或手动圈选。
- 类别差异只作可解释提醒，不自动驳回或悄悄改到其他部位。用户明确选中区域后，系统按该区域执行；明显错误的目标通过预览与纠正处理。

### 4.3 Mapping、编号与颜色

- 每条关系有不可变 ID 和项目内递增展示编号。编号显示 ①～⑤；底层保存整数，不依赖符号字符。
- 第一次用紫色，第二次蓝色，第三次橙色，第四次绿色，第五次玫红；颜色代表关系顺序，不代表物体类别。
- 同条关系贯穿源区域、目标区域、清单、展开的 Prompt 标签；不能只依赖颜色区分。
- 删除 ② 后保留 ①③④，其他关系不换编号或颜色。撤销恢复原 ID、编号及颜色。
- 超过五次历史创建时可以循环颜色，但编号继续递增。最多五条“当前有效关系”，不是最多创建过五条。
- “清空编辑”重置编号分配；生成历史和原始素材仍保留。“新建项目”才开启独立项目身份。
- 切换参考图不会丢失其他图的关系；点击清单可自动定位相应参考图和主图区域。

### 4.4 冲突与素材变化

- 同一目标重复拖拽：提示“替换已有操作 / 取消”；替换沿用原关系 ID、编号、颜色。
- 两条目标 Mask 有明显交叠：在清单标记冲突，并让用户修正、替换旧操作或删除；第一版不允许未解决冲突进入生成。
- 明显交叠的检测算法及阈值由 Codex 用真实案例验证并配置；不把接触边缘的小面积重叠一律视为错误。
- 更换主图：有编辑时提示将清空当前关系，确认后更换。只调整显示缩放不影响关系。
- 删除正在被关系引用的参考图：提示受影响的编号，确认后连同相关关系删除；可撤销。
- 修改或重新上传源图片不得套用旧 Mask；保留逻辑图片 ID 时也必须更新图像版本并使旧关系失效。

### 4.5 代理与变换（P1）

抠图叠加仅是“位置示意”，展示说明“最终由 AI 融合”，不冒充最终成图。

选中关系后可拖动代理、用滚轮调整大小；未选中时不拦截滚轮。缩放默认 100%，建议限制为 50%～200%，相对于默认贴合尺寸；第一版不开放旋转。

放置意图、原目标选区和实际允许修改区域是三件事。移动/放大后，目标清除区域与新对象可能占据的区域均需纳入编辑范围；更新后的范围必须可见，并再次参与冲突检测。不能只移动代理却仍用旧 Mask 请求生成。

替换穿戴商品时，源图和目标图姿态可能完全不同；二维贴图变换只表达大致意图。若上游不能可靠执行位置/尺寸控制，禁用生成相关变换控件并说明，仅保留关系选区，避免给用户虚假的控制能力。

### 4.6 撤销、保存与结果

- 撤销/重做覆盖新建、删除、换源、选区修改、变换和清空；一次拖动算一个动作，不把每一帧拆成历史。
- 若实现短标签，标签修改也加入撤销、重做、草稿和任务快照。
- 自动保存草稿时同时保存素材、选区、关系及补充要求。独立网站以服务端持久保存为准，浏览器缓存只作补充，不能只保存会过期的 blob URL。
- 草稿和历史在刷新、关闭浏览器、重新打开及应用重启后仍可恢复；存储失败显示“草稿未保存”，不能假报成功。使用同一已授权账户从新浏览器登录时也能查看历史；单使用者私有版本通过同一授权身份验证。
- 结果关联原始主图版本和此次关系快照。生成结果作为新主图时新建编辑版本，重新准备选区，不把旧坐标/Mask 默认复用到新图。
- 下载生成的真实文件，建议命名 `项目名_edit_时间.png`；输出格式以真实返回为准，不只改扩展名。

### 4.7 参考图裁剪与上下文保留

目的：减少无关人物、商品或背景参与参考，降低多参考图编辑时混淆关系的风险。是否改善效果，必须用同组真实素材比较，不承诺裁剪一定消除混淆。

- 用户确认源选区后，根据 Source Mask 计算外接框，并可生成带安全边距的局部裁剪，对应 `source.crop_id`。此步骤不调用图像生成，不改变用户已选对象。
- 初始实验可采用每侧 5%～10% 的边距：水平方向相对于外接框宽度，垂直方向相对于外接框高度；裁剪框限制在原图范围内。此比例可配置，不是最终固定值。
- 裁剪必须保留已确认的整个源选区；过小、空选区或明显缺损应提示纠正，不能仅靠扩大裁剪掩盖错误。
- 保留原始参考图和选区。服装、双鞋、遮挡等可能需要更多上下文时，可加大裁剪范围或使用整张参考图。不能禁止原图，也不能默认把所有原图再附送给模型。
- Codex 比较带上下文裁剪、完整参考图及可用的透明抠图后，选择默认输入策略。实际提交只包含本次相关素材，避免把未引用的参考图也发送给上游。
- 记录裁剪框在原图上的位置、裁剪尺寸及策略版本，使裁剪预览、Mask 和源锚点能相互转换。裁剪后的局部坐标不能替换原图锚点。
- 裁剪可以由前端或后端生成，部署位置由技术方案决定；不得绕过现有服务端模型调用与凭证管理。

### 4.8 Mask 边缘处理与修改范围

目的：给边缘重绘和融合留出合适空间。膨胀扩大区域，羽化软化过渡，两者不能等同，也不能保证模型自动处理透视、光照或阴影。

- 永久保留用户确认的原始目标 Mask；模型输入及可能的结果合成使用独立派生版本，不覆盖原始 Mask。
- 先核对实际接口的 Mask 语义：黑白取值、透明通道、尺寸、是否接受软边缘，以及多图输入时 Mask 作用于哪张图。转换在适配层完成，不将不同接口的 Mask 直接互用。
- 硬 Mask、膨胀后的硬 Mask、接口可用的羽化 Mask 应进行同组样本对比。仅在验证有效且不破坏目标外区域时启用对应处理；接口不支持时明确关闭。
- 4～8 像素可作为指定处理分辨率下的膨胀实验值；同时记录该分辨率。膨胀半径与模糊半径分别配置，不能对所有尺寸固定使用同一个数字。
- 使用派生版本扩大实际修改范围时，更新 `target.edit_region_id`，让用户能看到范围边界并重新检查冲突。原始选区轮廓与扩展范围采用不同线型，避免误以为选中了更大的对象。参数可自动处理，不要求用户手调。
- 若羽化用于生成后的回贴合成，需单独验证边缘双影、残留旧物体及阴影截断；不能假定与上游接受软 Mask 是同一能力。
- 任务快照记录所用原始 Mask、派生版本、处理参数和真实请求输入，方便复现与定位失败。

### 4.9 选区响应反馈与交互兜底

- 当前点的选区未准备好时，在光标旁或图片内显示轻量计算中状态；可采用微型 Loading，不强制自定义光标样式。计算失败改为可重试/手动选择，不无限转圈。
- Loading 只表示正在计算，不代表已有对象被确认。源选区未确认不能开始拖拽；目标仍在准备时，松手进入“确认目标”。
- 悬停请求采用停留触发或节流、缓存及最新请求优先；避免每个 `mousemove` 都发请求。不再需要的请求在可取消时取消，否则丢弃返回。
- 性能统计需包含用户停留触发的等待、队列、网络、解码及渲染，不能仅报告模型计算时间，或靠长时间停留门槛掩盖延迟。
- 先优化悬停路线。仍不满足第 8.3 节目标时，在 `TECH_RESEARCH.md` 提交真实量测、设备和网络条件、已尝试优化及备选体验，再按原 PRD 的产品确认规则决定是否启用点击识别。
- 点击识别模式的源侧流程必须完整：单击该处 → 计算并预览候选 → 用户确认 → 从已选对象按下拖拽。识别点击与拖拽起手不能混为同一次未确认事件。
- 目标侧保留着陆锚点；落点无有效候选时进入目标确认，允许点击、候选切换或圈选后确认；此时不新增 ready 关系。
- 当前交互模式明确展示，模式切换不丢已有 Mapping。不得在用户拖动过程中根据单次网络波动自动切换模式。

### 4.10 每条关系的短标签（P1）

- 在编辑清单每条操作的“修改”内提供可选“物品名称”输入；默认折叠，空值不阻塞生成。建议最多 10 个用户可见字符，例如“靴子”“红色 T 恤”。
- 标签用于命名和辅助指令，绑定对应 Mapping 的 `source.label`；用户填写时优先于自动名称，自动分类不能覆盖用户输入。技术上记录名称来源。
- 标签与关系 ID、参考图/裁剪索引、目标区域共同编译为明确指令。例如“操作②：使用参考对象②的红色 T 恤，替换主图目标②”。编号由适配层绑定到实际图片和区域，不仅依赖颜色。
- 标签不是模型官方的区域控制参数，也不能纠正错 Mask。选区不对时仍要求用户调整；标签变更不触发重新选区或付费生成。
- 标签更新支持撤销、保存、恢复，并包含在生成快照中。未实现此 P1 时，界面不出现虚假的标签功能，调研与默认 Prompt 仍须确保关系对应清晰。

### 4.11 生成历史列表与详情（P0）

- 一次有效生成提交对应一条历史记录，关联项目、编辑版本、不可变快照和任务；同次任务的重复请求只返回同一记录。生成前校验失败不创建付费执行记录。
- 已提交、处理中、成功、失败和部分完成任务均可查找；成功显示最终图缩略图，失败显示主图缩略图及失败状态，不能用主图冒充生成结果。
- 默认按提交时间倒序，显示项目名称、生成时间、状态和结果缩略图；有多个真实输出时显示结果数量，详情内逐张打开。时间按当前用户时区展示，后端统一存储时间基准。
- 使用分页或加载更多，避免一次加载全部原图。空历史显示“还没有生成记录”和“新建编辑”；列表或详情加载失败提供重试。
- 点击卡片或缩略图打开本站详情，默认显示真实生成图，可放大、原图对比及下载。失败记录展示失败原因、当次输入与恢复编辑入口；处理中记录继续显示任务进度。
- 详情展示本次主图、已引用参考图、Mapping 清单、补充要求、实际模型及可获取的尺寸/质量/费用。技术 Prompt 折叠展示，不把请求日志堆到用户主流程。
- 查看列表、打开详情、对比、下载和恢复编辑都不得调用图像生成；只有用户明确点击生成/重试才发起新的付费执行。

### 4.12 从历史恢复与继续编辑（P0）

历史详情提供两个不同入口，文案须明确：

| 入口 | 加载什么 | 原历史如何处理 |
|---|---|---|
| 恢复当时编辑 | 该次生成使用的原主图、参考素材、源/目标选区、关系编号颜色、已实现的变换/标签、补充要求及可恢复模型配置 | 从快照创建新的可写草稿；原记录与原输出保持不变 |
| 以结果继续编辑 | 选定生成结果作为新主图；原参考图可继续保留供选择；旧关系清空，编号重新开始，重新准备 Mask | 新草稿关联来源结果；下一次生成另建记录 |

- 恢复操作不自动重新生成、不收费。草稿必须真正恢复结构化 Mapping，不能仅把一张结果图放回画布或只恢复 Prompt。
- 当前工作区有尚未保存修改时，先尝试保存；失败时提示用户重试保存或明确放弃，不能直接覆盖丢失内容。
- 历史快照只读，恢复后的操作和生成不能改写原记录。保存新草稿时可沿用项目分组，但创建独立编辑版本并记录来源。
- 缺失某个源素材、Mask 或结果时，保留仍可访问内容，清楚标出缺失项；需要该素材的关系不得标为 ready。允许重新上传并纠正，但不能自动拿当前素材顶替历史素材。
- 历史模型或参数不可用时显示原始配置，提示选择当前可用配置；不自动换模型后生成。

### 4.13 素材持久化与历史删除（P0）

- 原主图、恢复所需参考图、原始与派生选区、裁剪、生成结果和缩略图均需持久保存。上游返回临时 URL 时，由服务端在有效期内取得文件并保存到网站自己的持久存储；历史保存资产 ID，而非仅存上游 URL。
- 生成完成但输出尚未存好时显示“生成完成，正在保存”。输出保存失败显示“保存异常”；优先重试获取/保存已生成文件，不再次调用生成。临时输出已过期且无法恢复时说明限制，不能假称成功或悄悄重新扣费生成。
- 默认保留历史直到用户删除；本期不做自动过期清理。容量不足、存储不可写时提前或及时报错；若技术环境必须有保留期限，需在方案中说明并让产品确认。
- 历史卡片“删除”需要用户确认，首版可采用逻辑删除，使记录从列表隐藏；不得同时删除其他历史、当前草稿或来源链路仍引用的素材。实体清理仅在确定无引用后执行，可延期实现。
- 所有历史查询、详情、下载和恢复请求检查身份/归属。单使用者网站也不能把凭证、私有素材或全部历史暴露为匿名公共接口。无需为本期增加复杂组织和角色系统。
- 浏览器刷新、服务器重启、重新部署不得使正式历史丢失；本地开发可用持久数据库与磁盘目录验证，正式运行须选用有持久保证的数据库及文件存储。

## 5. 状态与异常

交互状态与生成任务状态分别管理。

| 交互状态 | 行为 |
|---|---|
| 准备中 | 上传/图像准备/分割准备；有明确计算中反馈；可以切图，不能拖出未确认对象 |
| 源候选 | 悬停、候选切换或圈选；按下后锁定 |
| 拖动中 | 显示源代理；目标候选更新；Esc 或放到工作区外取消，不新增关系 |
| 待确认目标 | 目标仍在计算或不明确；选择候选/圈选，确认后创建关系 |
| 关系待执行 | 可定位、纠正、删除；检查冲突 |
| 任务处理中 | 对应快照锁定；本版可锁定当前编辑，刷新后恢复任务状态 |

| 任务状态 | 用户可见行为 |
|---|---|
| 校验失败 | 指明缺图、失效选区、冲突、参数超限或余额不足；不调用生成 |
| 排队 / 处理中 | 显示真实状态，不伪造百分比；按钮禁用，显示任务 ID 对应状态 |
| 成功 | 展示结果、对比、下载；记录实际执行策略与费用（若可获取） |
| 生成完成，保存中 / 保存异常 | 已得到输出但保存未完成；展示真实状态；重试保存不重新生成、不产生新的生成调用 |
| 部分完成 | 仅串行策略存在；显示已完成/未完成操作，允许下载带明确说明的中间结果 |
| 失败 | 保留草稿；展示可理解原因及重试入口 |
| 状态未知 | 请求超时但上游是否执行未知；先查原任务，不直接重复调用 |

具体处理要求：

- 上传失败可单图重试；跨域或图片下载失败要在准备阶段暴露，不等到生成才发现。
- 用户连续点击生成、前端断网重试、刷新恢复不得创建重复上游任务。服务端以项目版本及请求标识幂等处理。
- 上游明确失败可重试；每次新生成可能产生新费用，说明后由用户发起，不自动无限重试。
- 串行部分失败时仅在用户选择继续后执行剩余项，复用已确认中间结果；不从头自动重做并重复收费。
- 队列中取消与处理中取消分别处理；上游不支持停止时显示“当前任务无法停止”，不能承诺取消后不产生费用。
- 本期独立网站不新增商业余额系统；真实费用按实际渠道规则记录，不能把保存异常当成没有发生模型调用。若复用计费能力须在方案中核对其规则。
- 在历史页离开、刷新或关闭浏览器不取消已提交任务；后台完成后更新原记录，重新打开可查看。

## 6. 数据与系统职责

### 6.1 数据原则

**Mapping 是编辑状态的唯一依据，Prompt 是从状态生成的表达。** 切图、删除、撤销、恢复都操作结构化数据，不能从一段 Prompt 反推项目。

坐标以经过方向校正后的原图为基准，保存归一化坐标 0～1。显示缩放、留白、平移和缩略图坐标须转换到该坐标系。记录原图宽高及版本；Mask 必须可恢复到对应图像尺寸。

以下是内部数据示例，不是外部模型 API：

```json
{
  "schema_version": 1,
  "project_id": "project_001",
  "revision": 7,
  "next_display_index": 4,
  "main_image": { "id": "main_001", "version": 1, "width": 1200, "height": 1600 },
  "mappings": [
    {
      "id": "mapping_001",
      "display_index": 1,
      "color_token": "purple",
      "mode": "replace",
      "source": {
        "image_id": "ref_A",
        "image_version": 1,
        "anchor": { "x": 0.42, "y": 0.76 },
        "mask_id": "src_mask_001",
        "crop_id": "src_crop_001",
        "cutout_id": null,
        "label": null
      },
      "target": {
        "image_id": "main_001",
        "image_version": 1,
        "anchor": { "x": 0.51, "y": 0.83 },
        "mask_id": "target_mask_001",
        "edit_region_id": "edit_region_001"
      },
      "placement_intent": null,
      "user_instruction": "",
      "status": "ready"
    }
  ],
  "global_instruction": "保持人物姿势和背景，整体写实"
}
```

P1 开启时 `placement_intent` 保存统一坐标系下的期望位置、相对缩放及最终边界。还需保存图片资产、选区表示、任务快照、输出、中间结果、请求 ID 与可获取的费用；具体类型与接口由 Codex 技术方案确定。

V1.1 的内部元数据要求：裁剪框及边距策略、原始 Mask 与模型使用版本的关联、边缘处理参数/处理分辨率、标签来源（用户/自动/空）。可保存于关联资产及任务快照，不必将所有字段堆入 Mapping。旧项目缺少这些可选字段时按“未处理/无标签”读取，不得改写其原始图片或选区。

V1.2 历史数据最小关系：

| 数据 | 至少保存 | 约束 |
|---|---|---|
| 项目/草稿版本 | 项目 ID、所有者、名称、编辑版本、原图和参考资产、当前 Mapping、保存时间、来源历史/结果 | 可写；与历史快照分开 |
| 生成记录 | 记录 ID、所有者、项目/版本、提交时间、幂等标识、任务/上游标识、状态、错误、费用、删除标记 | 同一有效任务唯一；能通过稳定地址查询 |
| 不可变输入快照 | 本次真实素材版本、选区、关系、补充要求、模型及实际参数、编译策略版本 | 后续编辑不能覆盖；恢复据此建立新草稿 |
| 结果及素材资产 | 资产 ID、所有者、持久存储位置、格式、尺寸、缩略图、关联任务/结果、保存状态 | 不依赖临时 URL；共享引用不可误删 |

具体表、存储服务和接口由 Codex 选择并写入技术方案。历史恢复不仅依赖前端状态，也必须保存对应文件字节和完整素材关联；上游签名地址可以临时生成供访问，但不能作为唯一资产凭据。

### 6.2 职责边界

| 模块 | 责任 | 完成条件 |
|---|---|---|
| 前端 | 独立网站导航、上传、视图转换、选区可视化、拖拽、关系清单、撤销恢复、结果对比、历史列表/详情及恢复入口 | 完成编辑→历史→恢复的真实操作链路，所有状态可解释 |
| 分割适配层 | 图像准备、点/圈提示、候选选区、纠正、必要时抠图 | 真实图样本可用；量测冷启动和热态延迟 |
| 项目与任务后端 | 身份与归属、素材、版本、关系验证、历史记录/快照、幂等、后台执行、输出持久化、恢复、日志 | 关闭页面和重启不丢历史；打开与恢复不调用生成 |
| 图像模型适配层 | 读取能力配置，将关系编译为实际输入、调用与结果解析 | 所用字段有官方/渠道依据及真实调用证据 |
| 测试与验收 | 图像定位、状态恢复、真实效果及费用核对 | 第 8 节通过并附证据 |

核心链路不强制引入 Agent。图像分类或 Prompt 润色可以是辅助步骤，但不能让 Agent 任意改变用户已经指定的源、目标或操作数。

## 7. Codex 技术调研任务与实施门槛

### 7.1 先调查已有工程

先读 `AGENTS.md`、项目说明、技术栈、图片上传/存储、生成接口、用户资产、任务机制和现有 Mask/抠图能力；优先复用适合独立网站的模块。没有仓库时建立独立网站项目，包含前端、实际调用适配及持久化后端；技术验证可先局部模拟，但不能把仅浏览器缓存的页面作为最终网站交付。不修改未理解的生产功能，不凭记忆编造已有接口。

所有涉及模型、接口、许可证和部署限制的结论，要查当前一手资料并记录链接、检索日期和版本。先核对实际渠道契约，再以最小真实请求验证；官方模型支持某项能力不代表中转渠道也支持。

### 7.2 必须回答的技术问题

| 问题 | 调研及实测要求 | 输出 |
|---|---|---|
| 点提示分割如何实现 | 比较至少两条可获得路线，例如 SAM 类方案与托管分割服务；确认候选粒度、圈选纠正、许可证、下载体积、依赖及部署条件 | 候选对比、推荐及实际 Mask 样例 |
| 悬停是否能流畅 | 测图像准备、首次选区、缓存后从触发到可见结果的延迟；比较浏览器与服务端可行路线，记录设备/网络/分辨率；验证 Loading、节流、过期结果处理及备选模式 | 延迟记录、缓存策略、降级证据与完整操作路径 |
| 源图怎么传给模型 | 同组素材对比原图、带上下文裁剪（初始边距 5%～10%）、透明抠图对款式、完整性和姿态保持的影响；确认透明图和多图输入上限 | 真实输入输出、默认输入策略、裁剪转换元数据 |
| 目标区域怎么约束 | 验证原生 Mask/区域字段及其黑白/alpha 语义；对比硬 Mask、膨胀及接口接受的羽化；无原生能力时比较标注引导图、文字区域描述或合成布局图；不能把内部 anchor 当成官方参数 | 渠道能力表、处理参数、有效范围和适配输入示例 |
| 多对象如何防止混淆 | 固定样本检查图片索引、关系编号、目标区域和指令绑定；若做短标签，比较有无标签及错误标签时的影响 | 关系编译规则与真实效果，不能仅以标签存在宣称已解决 |
| 多条编辑怎么执行 | 同一组 2～3 条非重叠关系，对比一次多参考图编辑与串行编辑的效果、调用数、费用及耗时 | 选择依据及失败恢复方式 |
| 位置/尺寸能否控制 | 若做 P1，测试代理放置与最终结果是否一致，处理清除旧区域、新区域及冲突 | 能否启用的明确结论 |
| 目标外如何保留 | 对比上游生成保留程度；若考虑回贴原图，实测边缘、阴影及遮挡，不承诺无损融合 | 保护方案、质量与精度取舍 |
| 素材、历史及任务如何恢复 | 独立网站的数据库/文件存储、素材转存、任务查询、幂等、身份隔离、快照恢复及费用记录；实测关闭页面、临时 URL 失效和服务器重启 | 数据/资产流程、独立部署方案、历史接口与实测证据 |

点提示分割可能仍需全图编码。锚点首先减少选择歧义，不保证编码算力、带宽或首次耗时变小。是否更轻必须用量测证明。

### 7.3 不预先锁死生成策略

前端统一为一次点击执行全部编辑；后端可批量，也可串行。优先测试一次多关系编辑是否满足质量目标，再与串行比较。

串行不是默认更好：可能增加费用、耗时，并对已完成区域产生累计变化。批量也可能混淆参考图。选择需有相同样本的证据；只有满足必要质量时才采用较低调用数方案，不以节省费用掩盖质量问题。

串行还有版本问题：第一步生成后，后续目标选区不一定仍对应原图。需验证构图漂移；有漂移时重新定位并显示必要确认，不能盲用旧 Mask。不能实现安全续跑时，不宣称支持自动部分恢复。

## 8. 验收标准

### 8.1 功能与异常验收

| 编号 | 操作 | 可观察通过条件 |

| A01 | 上传主图及 A/B/C 三张参考图，反复切图 | 主图不变；缩略图正确；切换无拉伸、状态丢失 |
| A02 | 悬停裤子，模型选成人物；切候选或圈选 | 能确认裤子范围；不会被强制卡在错误候选 |
| A03 | 从 A 拖鞋到主图鞋的位置 | 显示同色同编号源/目标和清单；未调用图像生成 |

| A18 | 快速移动鼠标、切图，模拟慢返回或识别失败 | 显示正确的计算状态；旧请求不覆盖新图/新点；无大量无效请求或无限 Loading |

| A20 | 若实现短标签，输入/清空、撤销、刷新并生成 | 标签选填且绑定对应关系；用户名称不被自动覆盖；不会改 Mask；请求映射正确 |

| A25 | 从历史点击“以结果继续编辑”再生成 | 所选结果成为新主图；旧关系清空、选区重新准备；新记录关联来源，旧记录保留 |
| A26 | 处理中关闭浏览器，完成后再打开历史 | 原任务继续；原记录更新成功/失败；不重复提交或重复调用 |
| A27 | 让上游临时 URL 失效、清除浏览器站点数据或重启应用后打开历史 | 经相同身份授权仍能查看输出并恢复素材；使用持久资产，非缓存或临时 URL |
| A28 | 模拟已生成但资产转存失败，再重试保存 | 显示保存异常；复用已生成输出；不重新调用图像模型；存好才标记成功 |
| A29 | 删除一条历史后打开其他引用相同素材的记录及新草稿 | 被删记录隐藏；其他图片、历史和草稿仍可恢复；无误删共享资产 |
| A30 | 未授权访问历史详情或下载；若多人，用另一账户请求该记录 | 被拒绝；列表、素材、恢复接口均不泄露其他使用者历史 |

### 8.2 真实图像质量验证

先建立至少 10 个固定样本，以用户可提供的素材优先：单对象替换 3 例、两对象替换 3 例、三对象替换 2 例、遮挡/近景或源目标视角不同 2 例。难例不可用简单样本替代。

每例保留主图、参考图、选区、关系、输出、调用数、耗时和可获取费用。由产品依据以下标准判断，不以模型自评替代人工检查：

- 换对对象和区域，无漏项、串参考图或残留原商品。
- 商品核心颜色、款式、明显图案/标识符合参考图；文字细节无法保证时须记录失败，不能泛称“基本一致”。
- 目标处透视、比例、穿戴关系及遮挡自然，没有明显双影、断裂或粘贴边缘。
- 目标外人物身份、姿态、构图、背景没有明显非预期变化。
- 最终图片无编号、彩色蒙层或引导标记残留。

建议首轮质量门槛：10 例中至少 8 例以上各项均通过；任一多对象类别不能全部失败。此数字是 Demo 进入产品评审的门槛，不是线上 SLA，也不代表足够统计置信度。失败样本和适用边界必须保留，不能只展示成功案例。

### 8.3 性能目标

以下为待验证体验目标：已准备图片的本地拖动代理持续响应，不等待网络；已缓存图像的悬停选区 P95 目标不超过 300 ms。分别报告首次准备耗时和热态耗时，附测试硬件、网络、图像尺寸及测量次数。

悬停延迟从用户停留达到触发条件开始量至选区实际显示，并另外报告停留门槛；首次准备、排队、网络和渲染不可从用户实际等待中隐去。Loading 是反馈要求，不等于性能达标。需要点击识别兜底时，还须验证第 4.9 节的完整链路。

若候选路线达不到悬停目标，先优化缓存、降低准备分辨率或更换部署路线；仍不满足时提出“停留后识别/点击确认”等替代交互及影响，由产品确认，不能悄悄删去悬停能力。

## 9. 上线与交付边界

本次给 Codex 的执行目标是技术调研、实现与验证，不包含生产上线、替换线上功能或购买付费服务。真实分割及图像编辑调用使用用户提供且授权用于本任务的凭证、渠道与素材；不得将素材用于无关外部服务或公开展示。凭证缺失不阻塞其余独立工作。

交付独立网站的启动方式、环境配置、数据库与素材存储初始化、部署建议、迁移/回退办法及截图/操作录屏。生产发布仍需后续明确安排；本轮修改产品文档不要求立即建站或上线。正式运行的素材和历史不能存在临时执行目录或无持久保证的部署磁盘中。凭证仅放服务端配置，不写进前端或提交仓库。

排期不在本文件编造。Codex 输出阶段拆分、风险和依赖，项目团队据此确定工时、提测和上线时间。
